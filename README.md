# 群飞 · Reynolds 鸟群壁纸

基于 Reynolds Boids 规则的实时鸟群动态壁纸。默认 1500 只鸟在深色背景中聚散、转向。

画面由程序实时演算，每只鸟根据附近同伴的位置与方向作出反应。

![鸟群壁纸预览](preview.png)

## 群飞规则：

首先是 Reynolds Boids 的三个规则约束：

- **分离**：与过近的同伴保持距离。
- **对齐**：向附近同伴的飞行方向靠拢。
- **聚合**：向附近群体的中心靠近。
	

三个规则权重可以自定义修改。

### 触边：

在边框设置有区域增大鸟扭头往回飞的倾向（边框大小可调）。

若鸟飞出屏幕范围则视为死亡，死亡后会有新的鸟从屏幕外进入，保持屏幕内鸟数量与设置值一致。

## 不同选项解释：

以下范围与默认值对应当前 Web 版的 `settings.js`。距离和速度使用逻辑像素，不是显示器物理像素；系统缩放与渲染比例不会改变逻辑单位。百分比在页面中按百分数显示，配置文件中使用小数，例如 7% 保存为 `0.07`。

### 鸟群与运动

|选项（配置键）|范围 / 默认值|作用与调节效果|
|---|---|---|
|鸟群数量 `count`|0–3000；1500|目标人口，增减时逐渐进出场。设为 0 后等待鸟和残影消失即可进入空闲状态。|
|鸟体大小 `size`|1–16 px；6.58|只改变绘制大小，不改变 58 px 感知半径与 15 px 分离半径。大鸟仍可能在视觉上重叠。|
|飞行速度 `speed`|20–240 px/s；87|基础移动速度。高速下单步位移更大，边缘转弯空间更紧张，可能更频繁触边。|
|个体速度差异 `speedError`|0–50%；7%|每只鸟有稳定的个体偏差，常态速度在基础速度的 ± 此比例内变化；设为 0 时常态速度一致。|
|分离 `separation`|0–4；1.38|提高会更强地避开 15 px 内的同伴。为 0 只关闭分离，仍执行对齐与聚合。|
|对齐 `alignment`|0–4；1|向 58 px 内同伴的平均单位方向靠拢，提高后更容易同向飞行。|
|聚合 `cohesion`|0–4；0.65|向 58 px 内同伴的中心靠拢，提高后更倾向形成紧密群体，也可能增加局部计算密度。|
|边缘回转区 `edge`|0–35%；17.5%|按可用区域宽、高分别确定提前转向带，越靠近边缘，回转推力越强。设为 0 则关闭提前转向|

三项权重是各自作用力的倍率，不要求总和为 1。

### 外观与拖尾

拖尾长度受拖尾时长和鸟速度影响。

|选项（配置键）|范围 / 默认值|作用与开销|
|---|---|---|
|显示拖尾 `trails`|开 / 关；开|显示最近的真实飞行轨迹。关闭可减少轨迹生成、上传与绘制，但历史仍继续保存，重新开启可立即显示。|
|拖尾时长 `trailDuration`|0.1–0.5 s；0.28|决定可见历史的时间范围。速度越快，相同时长的拖尾越长；时长越大，通常需要绘制更多线段。|
|拖尾采样率 `trailHz`|10–60 Hz；30|控制绘制时从历史中取样的密度，越低线段越少、弯曲处越粗略。历史仍按 60 Hz 记录，不会降低群飞模拟频率。|
|鸟群颜色 `color`|颜色值；`#84D8E0`|渐变配色关闭时，统一控制鸟体和拖尾颜色。开启渐变配色后，色相由下文的分群传色规则控制。|
|亮度 `brightness`|0.1–2；1.31|调整鸟群亮度，不改变飞行和近邻关系。|
|对比度 `contrast`|0.5–2；1.2|调整鸟体与拖尾的颜色对比度，不改变运动。|
|鸟群渐变配色 `randomColor`|开 / 关；关|增加同向分群、领鸟选择与颜色跟随计算；只改变配色。具体规则见下文。|

### 控制与互动

若在 `Wallpaper Engine` 上加载，仅有 **鼠标避让与点击** 正常显示。

- **暂停 / 继续**：冻结模拟时间、死亡动画、颜色变化与轨迹老化。暂停时仍可调整外观并重绘。
- **重置鸟群**：以当前设置重新创建鸟群并清空历史，不恢复默认参数。
- **导出设置**：下载包含设置、运行环境与诊断信息的 JSON，便于对照本机情况。
- **鼠标避让与点击**：指针附近产生避让，点击产生衰减排斥，并让附近鸟获得短暂约 10% 增速；重复点击刷新增速时限，不无限叠加。桌面模式需要宿主转发鼠标输入。
- 设置自动保存到当前浏览器来源的本地存储；不同浏览器、文件来源或 Wallpaper Engine 副本不保证共享设置。旧版的 K 值、动态图刷新率、预测时长已不属于当前选项，不能用它们调整现版本。

### 鸟群渐变配色规则

- 每只鸟进场时获得随机本色，终生保留；补生的新鸟重新选色。配色使用独立的种子散列。
- **先判断是不是同一鸟群**：58px 范围内、飞行方向差不超过 45° 才算有效同伴；周围至少有 4 只有效同伴的鸟构成密集核心。只有核心之间可以连接，并要求合并后的整个核心群方向跨度不超过 90°，防止稀疏鸟链或逐渐转向的长链把全屏串成一群。
- **外围跟随但不串群**：外围鸟只归属最近的同向核心，不能作为两个核心群的桥梁，也不参与领鸟选举；没有核心可跟随的鸟缓慢回到本色。迎面或垂直交汇的群体不会仅因位置重叠而共用领鸟，密集且同向靠拢的核心群则可以合并。
- **每群独立选领鸟**：每 0.1 秒更新分群和领鸟，按各自群体的平均飞行方向投影，从本群密集核心中选择最前方最多 3 只鸟，前排对跟随者影响更大。完全静止的群体不指定屏幕方向的「前方」。这些判定只影响配色，不改变原有运动规则。
- 领鸟不互相跟色，而是缓慢回归各自的出生本色。跟随者按 **65% 领鸟当前颜色、35% 自身出生本色** 确定目标色相，沿色相环短方向缓慢趋近；跟随的是领鸟正在变化的颜色，不是直接跳到领鸟最终本色。各群可因领鸟不同呈现不同色彩倾向，同时保留个体色差。
- 合群、分群或转向后重新选择领鸟：升到前排的鸟开始回归本色，落到后面的鸟开始跟随新领鸟，角色变化不硬切颜色。脱离同伴的鸟缓慢回到本色。不再使用全群平均色、屏幕位置染色或统一绕色环的自动变色。
- 拖尾记录飞过时的颜色，包括已消失个体的残留轨迹；暂停时切换配色或拖尾仍可重绘，关闭拖尾不会清除历史。
- 保留原有 `randomColor` 存档键及默认关闭状态，不覆盖已有设置。Wallpaper Engine 导入的是副本，更新文件后需重新导入或替换其项目副本。

## 算法优化逻辑

### 1. 完整半径规则与同步更新

每个固定模拟步读取同一份旧位置和速度，先计算新状态，再统一提交，避免先更新的鸟影响后更新的鸟。对齐使用平均单位方向，聚合使用相对位置均值，分离对近距离同伴施加随距离变化的排斥；转向还受角速度上限约束，避免瞬间掉头。

当前只保留 **58 px 完整圆形邻域、15 px 分离邻域**。

### 2. 空间哈希网格减少全局遍历

当前每步将可参与近邻计算的鸟放入 **40 px 网格**，查询时只访问与感知范围包围盒相交的格子，再用距离平方判断是否真正落在圆内。

网格使用预分配的桶、链表与数值数组；哈希冲突时核对真实格子坐标，结果缓冲按容量分配。

在大部分情况下，时间复杂度可视为O(N)：

**但当大量鸟聚在一起，局部邻居数量仍可能快速增加。**

### 3. 整格统计复用，边界逐只精算

每步预先统计格子内的数量、位置和单位方向之和。如果某个格子完整落在查询圆内，且不存在混合坐标的哈希冲突，就累加整格统计。

与圆边界相交的格子继续逐只检查距离。15 px 内的分离力依赖每只鸟的具体距离，因此仍逐只计算；只有整格确定在分离范围外时才跳过分离扫描。

### 4. 固定模拟步长与提交节拍

模拟固定 60 Hz，绘制独立限帧。绘制时先提交已完成的状态，再计算后续固定步，让 GPU 工作与 CPU 模拟有机会重叠，并减少模拟耗时变化对提交时刻的影响。高刷新率回调保留限帧余量。

单次回调最多追赶 4 个模拟步；过载时丢弃无法及时消化的积压时间，避免越追越慢。因此严重过载会损失模拟时间，平均 FPS 之外还要关注丢弃时间与帧间隔。暂停或页面隐藏时取消动画循环，恢复时清空积压；目标为 0 且所有鸟、残影与点击效果消失后停止持续刷新。

### 5. 历史轨迹、缓存与批量绘制

- 使用预分配数值数组与环形历史，按 60 Hz 记录位置、时间和色相，避免不断创建轨迹对象或移动整个历史数组。
- 鸟体和拖尾通过 WebGL2 实例化批量绘制，常见有鸟有拖尾场景为两次绘制调用，避免逐鸟提交。
- 拖尾根据历史版本、可见时长、采样率及时间基准判断是否需要重建；历史不变时复用已上传部分，只补必要的头部连接。GPU 根据时间计算拖尾衰减，颜色、亮度等通过着色器参数应用。
- 历史时间使用双精度保存，GPU 使用相对时间，减轻长时间运行后的时间精度问题。死亡或离场后的轨迹放入独立残影池，新鸟复用槽位时不会继承旧尾迹。

### 6. 生命周期与配色逻辑

数量增加时以约 450 只/秒逐步补生；减少时让鸟离场。活动鸟触边时先求运动线段的首次接触点，在那里执行约 0.28 秒死亡动画，再按最新目标人口补生，避免高速移动穿过边界后继续存活，也避免旧补生任务与新数量冲突。

边缘使用逐渐增强的回转力，并在正对边缘时加入侧向转弯，打破纯减速不能改变朝向的对称情况。渐变配色把分群和领鸟更新降到每 0.1 秒一次，期间缓慢过渡颜色；出生色使用独立散列，不消耗运动随机序列。具体分群约束见前文。

### 在自己的机器上观察

打开页面设置面板，等待目标鸟数补齐、群体稳定后，观察帧率、帧耗时、模拟耗时、绘制耗时和 GPU 耗时；`—` 表示运行时没有提供该测量。60 FPS 的单帧时间参考为 16.67 ms，30 FPS 为 33.33 ms。比较配置时应保持数量、逻辑视口、缩放、拖尾、配色、帧率上限和宿主一致，并记录采样时长。

需要降低负载时，可减少数量以减轻近邻计算，降低拖尾时长或绘制采样率以减少轨迹开销，降低渲染比例以减轻像素负载，或降低帧率上限以减少绘制。降低绘制帧率仍保留 60 Hz 固定模拟步长，因此不代表 CPU 模拟工作量按比例下降。


## 使用方式

**Wallpaper Engine**：通过页首的创意工坊链接订阅并应用，在壁纸属性面板中调整效果。桌面鼠标互动取决于 Wallpaper Engine 的输入转发设置。

**浏览器**：直接打开 [index.html](index.html)，无需安装依赖、联网或构建。

项目使用 JavaScript 与 WebGL2，需要支持 WebGL2 并启用硬件加速的运行环境。

实际流畅度取决于设备、分辨率和设置。

任务栏自动避让依赖宿主提供的工作区信息，必要时可用四边留白手动补偿。

# WASM优化：验证与发布依据

2026-10-29。对照基线为本仓库旧 JS 实现 `e0be495`（“优化流畅度”）。用户要求：**只有比现有 JS 版有提升，才覆盖并上传**。本次在下面限定场景中测得模拟与完整画面主线程耗时降低，因此批准切换；不宣称语言天然更快、任意机器稳定60FPS或功耗同比下降。

## 实现范围

- 复用 C++ `Simulation`，Emscripten 6.0.13 / `-O3` 编译，浏览器强制单参与线程；没有 pthread、SharedArrayBuffer 或跨源隔离要求。
- `SINGLE_FILE=1` 将 WASM 内联在 `boids-wasm.js`，全部资源离线，已经实际从 `file://` 加载，不需要 HTTP 服务或 Emscripten 运行环境。
- WebGL2 实例化鸟体和真实历史拖尾，沿用原生鸟体网格、扑翼、死亡和历史插值公式；不是录制视频，也不是改用旧 JS 模拟作为回退。D3D/WebGL 不承诺逐像素一致。
- 固定60Hz模拟，帧率控制只约束绘制提交。暂停取消RAF，恢复清空时间债务；数量归零、鸟和残影退完后真正停帧。宿主参数、四边距、显式任务栏方位/厚度、窗口缩放、点击、渐变均接入。
- C++ 近邻候选读取改为24,000字节的紧凑位置缓存（3000容量），不改变半径、候选顺序或算术，不用近似、截断邻居或降低画质换成绩。

## 一、受控 JS / WASM 模拟对照

同一 Chromium 156 / V8 环境，同一个页面串行运行两种核心；其余动画暂停。视口1440×900，1500/3000只，完整58px感知与15px分离半径，速度87、速度差7%、权重1.38/1/0.65、边缘0.175、拖尾0.28秒/30Hz，单色/渐变分别测量。

两端注入**同一份 Float32 初始位置和速度**，全为Active、id从1开始、速度偏差0。初态PRNG为xorshift32、种子555294758；均匀点在距四边80px内区，密集点在 `[440,1000]×[270,630]`；方向均匀、速率87。预热60步、测300步，每步1/60秒；JS计时包含 `Simulation.step + History.record`，C++的历史本来就在step内。没有渲染。顺序JS→WASM、WASM→JS、JS→WASM，共三轮。

## 二、真实浏览器完整画面对照

为避免只测CPU内核而掩盖跨语言/上传/绘制成本，另外运行两个版本的真实入口。Chromium 156、NVIDIA RTX 4060 Laptop GPU / ANGLE D3D11，1440×900 CSS视口、DPR1.25（1800×1125绘制像素），3000只，帧率上限60，其余上述默认画质一致、避让和手动边距关闭。页面在前台，另一页面暂停；每轮reset到种子20261022，出生预热10秒、采样15秒；顺序JS→WASM、WASM→JS。

外部临时探针测量每次RAF回调执行前后的 `performance.now()` 差值，并将期间执行了真实WebGL实例绘制的回调记为提交。它包含模拟、历史/几何准备、上传/绘制调用和UI，可能包含调度等待；**是主线程回调墙钟耗时，不是进程CPU独占时间、GPU耗时、物理呈现率或电功耗**。两套自然演化轨迹并非完全相同。

|轮次|实现|回调耗时 ms/墙钟秒|提交/秒|提交间隔P95 ms|采样模拟步|
|---:|---|---:|---:|---:|---:|
|1|旧JS|653.604|59.994|33.500|899|
|1|WASM|384.495|59.999|22.300|900|
|2|WASM|397.280|59.998|22.100|900|
|2|旧JS|733.472|60.017|23.700|901|

两轮平均回调耗时从693.538降至390.887 ms/秒，降低约**43.64%**，并保持约60次提交/秒、约60Hz模拟。采样前后人口均为3000；JS采样期间丢弃模拟时间增量0。WASM约15秒内执行900步。收益不是“FPS翻倍”。P95仍大于16.67ms，**不签核90%逐帧间隔达到60FPS或显示器真实呈现**。

原始结果（含视口、设置、前后人口和模拟计数）：[js-wasm-live-results.json](evidence/js-wasm-live-results.json)。先前一次后台节流导致约1FPS、人口不足且视口不一致的试采明确作废，未混入上述结果；本地工作区保留无效记录。

## 三、正确性和真实运行

### C++ 与浏览器

- 正式3000容量原生构建，11组行为检查通过：完整半径独立oracle、phase过滤、触边死亡、入场、任务栏排除、安全穿越、人口收敛、速度/独立权重、点击、历史/暂停、时钟重基、颜色与线程确定性。
- 紧凑位置缓存优化前后，1800步取61个完整状态指纹，旧版1线程、新版1/8线程完全一致。覆盖Bird、Ghost和全部历史点、时钟、phase统计、候选数、精确邻居结果；最终 `1799,9d2053714697d36d`。抽样哈希不是对所有输入的形式证明。
- 新原生exe在副屏真实运行3000只、8线程、12秒，正常退出并捕获1920×1080 GPU图像；本轮没有重新测量原生高容量或热稳态。
- WASM浏览器实际检查：1500人口正常出生；暂停700ms时模拟步、时钟和提交数均冻结；暂停改色/缩放只重绘一次而不步进；恢复1秒推进60步；暂停状态下通过 `WEBGL_lose_context` 真实丢失/恢复资源，重绘成功而模拟不推进。
- 归零后鸟和拖尾均为0，700ms内模拟步/提交数不变；再改100只成功出生、恢复模拟。`file://` 离线入口无页面错误；768/390宽设置抽屉无水平溢出，实际检查画面。
- 已从迁入后的仓库根入口实际加载WASM；模拟WE全局上限5FPS、本地上限60时，2秒提交11帧而模拟推进119步，确认绘制遵守较低宿主上限且模拟不降为5Hz。更换同名入口后浏览器曾命中旧JS缓存，硬刷新后通过；更新项目时应重新加载壁纸。
- 发布目录自身的 `native/build-web.ps1 -EmscriptenPath …` 已实际重建72687字节的 `boids-wasm.js`；`native/build.ps1 -Tools -Verify` 也从仓库内源码完成原生构建并通过11组检查。重编译后的根入口已硬刷新加载，表单键盘调节速度仍保持暂停并生效，无页面错误。

[行为检查摘要](evidence/behavior-smoke.json)，[原生缓存性能摘要](evidence/cpp-compact-perf-summary.json)。原生新旧单线程三轮耗时降低3.99%–8.76%，8线程介于慢1.54%与快6.01%；这部分不是上面JS/WASM收益的替代证据。

## 四、发布边界与复核

- 发布依据是本机上述受控模拟和完整浏览器场景的耗时收益，以及实际WE窗口功能验证；不是其它GPU、CEF版本、长时间锁屏/休眠、多屏物理输入、桌面长期运行或功耗保证。
- WASM单线程不等于原生最多8线程的性能；默认1500、正式上限3000不变。任务栏位置/厚度由用户指定，浏览器无法读取Win32任务栏矩形。旧JS浏览器localStorage不自动迁移。
- 临时测量桥接、脚本与测试专用API不进入运行包。源码构建命令见根README；可用 `git show e0be495:<文件>` 查看本次被替换的JS基线。所有证据保留测量口径，不能把模拟毫秒倒数当成桌面FPS。
